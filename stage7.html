🧩 子过程：call + 标签 + goto :eof

      
@echo off
call :say hello          &:: 跳到 :say 执行，带一个参数
echo 回到主流程           &:: call 会"回来"，goto 不会
goto :eof                &:: 主流程到此结束，防止掉进子过程

:say                     &:: 子过程定义（标签）
echo [子过程] 收到参数：%1
goto :eof                &:: 子过程返回

      
两个 goto :eof 别混淆：主流程里那个是"防止脚本掉进子过程"的挡板；子过程末尾那个是"返回调用处"。call 是"去而复返"，直接写标签名或 goto 是"有去无回"。

    

  


  
  

    
互动 4 · errorlevel 分支实验室（脚本怎么知道成败）

    
每条命令结束都会留一个退出码：0 = 成功，非 0 = 出事。脚本的"智能"全靠它。点两个按钮，观察分支走向（阶段①动画讲过：这是命令留给脚本的"遗言"）。

    

      

      

        

          
          check.bat · 模拟运行
        

        

      

      

      
@echo off
ping -n 1 %1 >nul 2>nul          &:: 静默 ping，丢掉输出只留退出码
if errorlevel 1 (
    echo 【失败】%1 ping 不通，退出码 %errorlevel%
    exit /b 1                     &:: 以失败码结束脚本
)
echo 【成功】%1 在线，退出码 %errorlevel%


      

        
写法含义备注

        
          
if errorlevel 1退出码 ≥ 1 时成立老写法，兼容一切 Windows；注意是"≥"

          
if %errorlevel%==0退出码恰好等于 0现代写法，要用延迟展开的场景记得 !errorlevel!

          
命令A && 命令BA 成功才执行 B一行式分支：ping 主机 >nul && echo 在线 || echo 失联

          
exit /b 1脚本以此码结束调用方拿到 1 就知道你失败了——脚本的"礼貌"

🛠 动手任务（回到真电脑）

        
任务：写 backup-numbered.bat——每次运行都把 C:\练习\重要 打包备份成带序号的副本。

        
@echo off
setlocal enabledelayedexpansion
if not exist "%~dp0备份" md "%~dp0备份"
set /a n=1
:number
if exist "%~dp0备份\backup-!n!.zip" (
    set /a n+=1
    goto :number
)
tar -a -c -f "%~dp0备份\backup-!n!.zip" "%USERPROFILE%\Documents\重要" 2>nul
if errorlevel 1 (echo 备份失败 & exit /b 1)
echo 已生成 备份\backup-!n!.zip ✓

        
考点全在这 20 行里：延迟展开、goto 循环找空位、%~dp0 便携路径、tar 打包（Win10+ 自带）、errorlevel 收尾。跑三次，应该得到 backup-1/2/3.zip。

      

      

        
📚 深入资源（全球最好的批处理资料）

        
Robert van der Woude 的脚本百科——1997 年至今持续更新的个人站，几百个批处理实例 + FOR 命令圣经页 + 字符串技巧表，被全世界运维奉为圣经。冷门但封神。

        
批处理之家（bathome.net）——中文圈最活跃的批处理论坛，"BAT 求助"板块大量真实案例，搜报错关键字常能直接捡到答案。

        
SS64 CMD 参考（ss64.com/nt）——每个命令一页，标注哪些是内部命令，社区评价"比官方文档还好用"。

        
DosTips 论坛（ dostips.com）——英文批处理深水区，变量延迟黑科技大多出自这里。

        
通关标准：不看教程能独立写出 backup-numbered.bat，并能解释清楚为什么第 8 行要用 !n! 而不是 %n%。
